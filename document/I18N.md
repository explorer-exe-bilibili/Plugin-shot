# 多语言（i18n）协议

这份文档定义"界面文案怎么跨语言、跨插件共享"：语言偏好、两个 i18n 列表的 schema、
文本 key 的书写与回退链、插件侧 helper 与宿主侧 `Host::I18n` 的分工，以及本期的
明确限制。**新增用户可见文案、给配置项改 label、或者给插件加语言表之前先读这里**；
通用列表协议本身见 [`LISTS.md`](LISTS.md)，配置/设置页链路见 [`SETTINGS.md`](SETTINGS.md)。

**零 ABI 改动**是硬约束：i18n 只用 `shot.host.plugin_lists` + `lists.*` 事件，
不改 `include/plugin_api.h`、不新增 interface id / 宿主服务 / 插件能力，
`SHOT_ABI_MINOR` 不动，插件 metadata 也不用加字段。

## 1. 设计：数据形状不进 ABI

i18n 没有引入任何新 ABI，而是复用"数据列表 = list id + JSON schema"的通用容器：

```text
插件 create()
  └─ shot::I18n::loadTables(kLangTables) ── lists.add ──▶ i18n_source_list
                                                           （每插件贡献 {id, texts:{tag:text}}）
宿主 main 线程 tick
  └─ HostListCatalog::rebuildI18nListLocked()
        i18n_source_list + core 文案 + 语言偏好 ──▶ 生成只读 i18n_list
        └─ lists.changed({"list":"i18n_list"}) ──▶ 设置页/托盘/其它插件刷新

消费方（设置页 / 托盘 / 插件）
  display(owner, textOrKey) = i18n_list[(owner, textOrKey)] ?? textOrKey
```

三条长期约定：

1. **数据列表里直接放 key**：`config_list` 的 `label`/`tooltip`、`tray_command_list`
   的 `label` 都允许是"字面量或文本 key"。所有显示方统一用上面的 `display` 规则；
   老插件把中文直接写在 label 里 → 查不到 → 原样显示（**零破坏、不用重编**）。
2. **谁渲染谁解析**：设置页解析配置项的 label/tooltip/ENUM 选项；托盘解析菜单
   label；插件自己的气泡/覆盖层用 `shot::I18n::tr()` 本地解析。
3. **宿主自己产生、被原样展示的文本由宿主本地化**，不走 key：插件注册表 `reason`、
   `capture.failed.reason`、`lists.updated.reason` 等。参数只有宿主知道，消费方只
   负责显示。

## 2. 两个列表

### 2.1 `i18n_source_list`（插件贡献）

插件在 `create()`/`init()` 里通过 helper 把自己语言表归一成条目后 `lists.add`：

```json
{"list":"i18n_source_list","owner":"hotkey.main","items":[
  {"id":"config.capture_hotkey.label","texts":{"zh-CN":"截屏热键","en-US":"Capture hotkey"}},
  {"id":"config.capture_hotkey.tooltip","texts":{"zh-CN":"按一次组合键…","en-US":"Press a combo…"}}
]}
```

| 字段 | 类型 | 必填 | 含义 |
| --- | --- | --- | --- |
| `id` | string | ✅ | 文案 key，在同一 owner 内唯一（通常等于"被解析的字段值"） |
| `texts` | object | ✅ | `语言标签 -> 文本`；标签按 BCP-47，可写 `zh-cn` 等非规范写法（宿主归一） |

- 写：插件 `lists.add` / `lists.remove`；owner 必须是当前已加载插件 id；宿主按
  `(owner,id)` upsert；插件卸载时宿主自动 `removeOwner` 清掉它的全部贡献。
- 读：宿主只读；**插件不能直接读 `i18n_source_list` 做解析**——解析一律走
  `i18n_list`，这样消费方只需理解一份数据。
- 单条事件负载上限 64 KiB，helper 已按估算大小分块。

### 2.2 `i18n_list`（宿主生成、只读、当前语言快照）

宿主按当前语言把 core 文案 + 所有 `i18n_source_list` 条目投影成一份快照：

```json
[
  {"id":"@meta","language":"en-US","fallback":"en-US"},
  {"owner":"core","id":"settings.open","text":"Open settings"},
  {"owner":"core","id":"zh-CN","text":"简体中文"},
  {"owner":"hotkey.main","id":"config.capture_hotkey.label","text":"Capture hotkey"}
]
```

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `id` | string | 条目 id；首条固定是 `@meta` |
| `owner` | string | 贡献方：`"core"` 或插件 id（`@meta` 没有 owner） |
| `text` | string | 该 key 在当前语言下的文本 |
| `language` | string | 仅 `@meta`：当前生效语言（BCP-47） |
| `fallback` | string | 仅 `@meta`：当前语言回退链的下一站（zh 系为 `zh`，默认语言为 `en-US`） |

- **插件不能 add/remove `i18n_list`**：它是宿主生成的 `generated` 列表，写入口
  直接拒绝并 WARN（防手滑；`config_list` 同样处理）。
- 生成时机：启动加载完成后至少一次；`core/language` 变化；`i18n_source_list`
  贡献变化；插件启停/卸载清理。全部在 `HostRuntime::tick` 里重建完再统一
  `flushChanged`，每轮每个 list 只发一条 `lists.changed`。
- 变化通知**只复用 `lists.changed`**（负载 `{"list":"i18n_list"}`），不新增事件主题。

### 2.3 解析规则（所有消费方必须一致）

```text
display(owner, textOrKey) = i18n_list[(owner, textOrKey)] 存在 ? text : textOrKey
```

- ENUM 选项也走同一规则：`display = resolve(owner, optionValue) ?? optionValue`。
  core 语言下拉因此能显示「跟随系统 / 简体中文 / 繁體中文 / English」，日志级别
  能显示「调试 / 信息 / 警告 / 错误」，而配置里存的仍是技术值（`auto` / `debug`）。
- 查不到时**原样返回 key/字面量**：这是老插件与新宿主、新插件与老宿主之间的
  兼容兜底，不是错误。

## 3. 语言偏好与语言注册表

### 3.1 `core/language` 配置项

- 宿主设置里的 `core/language`（ENUM，默认 `auto`）：`auto|zh-CN|zh-TW|en-US`。
- `set_config` 立即切换当前语言（与其它配置一致，落盘由 `lists.commit` 负责）；
  `HostRuntime::tick` 每轮对比当前语言，发现变化就强制重建 `i18n_list` 并刷新
  注册表快照——所以走 `applyStored` 回灌、`host.config` 写入这类非 `lists.update`
  路径切语言也不会漏重建。
- 语言注册表在 `src/hostI18n.cpp`：`tag + 原生显示名 + fallback`，表驱动；
  语言 ENUM 候选与 `i18n_list` 的 `@meta`、`fallback` 都从注册表来，**不硬编码
  只有中英**。设置页语言下拉的显示名由 `HostListCatalog` 从注册表直接投影成
  `i18n_list` 的 core 条目（原生名不随界面语言变化）。
- 加语种 = 注册表加一行 + 宿主文案表每条加一项 `{tag, text}` + 各插件语言表加一张
  JSON——**不改宿主代码、不改列表协议**。
- 当前注册表包含 27 个标签：zh-CN / zh-TW / en-US，以及 fr-FR / de-DE / es-ES /
  pt-BR / it-IT / nl-NL / sv-SE / da-DK / nb-NO / fi-FI / pl-PL / cs-CZ / sk-SK /
  hu-HU / hr-HR / tr-TR / ru-RU / uk-UA / bg-BG / el-GR / ja-JP / ro-RO / id-ID /
  ms-MY。
  **其中只有 zh-CN 与 en-US 有译文**；其余可以选择，但未翻译文案按回退链落 `en-US`
  （zh-TW 落 zh 族简体）。它们都使用当前字体（`msyh.ttc`）覆盖的 Latin /
  Cyrillic / Greek 字母与日文假名/汉字（韩/泰/印地/阿拉伯/希伯来/越南等实测缺字形，
  未注册）。
- `auto` 的解析：Windows 用 `GetUserDefaultLocaleName`；其它平台回退 `en-US`；
  系统标签不在注册表里时先按主语言族匹配已注册语言（如系统报 `zh-HK` 落到
  `zh-CN`），仍没有才回退 `en-US`。

### 3.2 回退链（选文本，不是选语言）

```text
完全匹配（大小写不敏感，_ 视同 -）
  → 主语言（zh-CN 先试 zh；zh 语言族可命中 zh-CN 表）
  → 默认回退语言（en-US；en 语言族可命中 en-US 表）
  → 该 key 第一条可用文本
  → key 本身（连一条文本都没有时，消费方原样显示）
```

首批翻译只有 zh-CN + en-US：选择 `zh-TW` 时 zh 族没有专门文本，会落到
`zh-CN` 的简体文本（**不是**繁体），这是本期的已知限制，见 §7。

## 4. 文案归属与不翻译的东西

| 谁产生 | 怎么本地化 | 例子 |
| --- | --- | --- |
| 插件贡献的数据字段（`label`/`tooltip`/ENUM 选项） | 值写成 key，消费方 `display()` 解析 | `config.capture_hotkey.label` |
| 插件自己绘制的 UI（气泡、覆盖层、提示） | `shot::I18n::tr(key, 中文兜底)` 本地解析 | `ui.save_failed` |
| 宿主预置数据（托盘命令、core 配置项） | 宿主把 label 写成 key，宿主文案表按语言生成 `i18n_list` 条目 | `capture.request` |
| 宿主生成、被原样展示的文本 | 宿主 `Host::I18n::Message` 按当前语言生成 | 注册表 `reason`、`capture.failed.reason` |

**一律不翻译**（写死为中文/技术值，翻译会破坏协议或验证体系）：

- 日志（`shot::Logger` / `spdlog`）：e2e 按中文日志断言，日志正文保持中文；
- 事件主题（`capture.request`、`lists.changed`…）、配置 key（`logging.level`）、
  列表 id；
- ENUM 的**存储值**（`auto` / `debug` / `png`）：只有显示名本地化；
- 插件 metadata 的 id/版本、窗口类名、DLL 名。

## 5. 插件侧用法（`shot::I18n`，header-only）

```cpp
#include "shot_plugin_helpers.h"   // 也可以只包含 shot_plugin_helpers/shot_i18n.h

// 一个 DLL 一个插件 / 一个 DLL 多个插件都行：owner 必须是被解析条目的 owner。
const char* const kLangTables[] = {
    R"json({"@meta":"zh-CN","config.strength.label":"强度"})json",
    R"json({"@meta":"en-US","config.strength.label":"Strength"})json",
};

// 在能拿到 ShotHostServices* 的生命周期回调里（create/init/start）：
m_i18n = std::make_unique<shot::I18n>(host, "example.invert");
m_i18n->loadTables(kLangTables, std::size(kLangTables));

// 自己的文案（本地表 O(1)，查不到返回中文兜底）：
label = m_i18n->tr("config.strength.label", "强度");

// 数据列表里的 key/字面量（查 i18n_list 缓存；老宿主原样返回）：
name = m_i18n->resolve(owner, item.label);
```

- 语言表：**每语言一张 JSON 对象**，`@meta` 必填；非法 JSON / 缺 `@meta` /
  各语言 key 集不一致 → 只 WARN，插件不失败（能用的部分照常加载）。
- helper 内部订阅 `lists.changed`，`i18n_list` 变化后下一次查询重读快照；
  渲染帧里只有 map 查找，不会每帧查宿主。
- 降级：老宿主没有列表服务 → `available()==false`，`tr()` 用第一张表、
  `resolve()` 原样返回；返回的 `const char*` 在 `i18n_list` 变化/对象销毁后失效，
  要长期持有请拷成 `std::string`。
- 对象不可拷贝/移动，状态里用 `std::unique_ptr` / `std::optional` 持有；
  销毁时自动退订。

## 6. 宿主侧（`Host::I18n`）

`include/hostI18n.h` + `src/hostI18n.cpp`，一个进程一个单例：

- `languages()` / `findLanguage()` / `normalizeTag()` / `detectSystemLanguage()`：
  语言注册表与 auto 解析；
- `loadPreference()` / `setPreference()` / `preference()` / `language()` /
  `fallbackLanguage()`：语言偏好与当前语言（启动时 `HostRuntime::init` 读配置，
  运行期由 `HostConfigurable` 的 `set_config` 写入）；
- `text()` / `textIn()` / `format()` / `formatIn()`：宿主文案表（显示文案 + 动态
  消息）；每条文案的 `texts` 是任意语言的 `{tag, text}` 列表，选文本按 §3.2 的
  回退链；`Message` 类把"消息 id + 参数"延迟到渲染时按语言生成；
- `pickText()` / `pickTextIn()`：按 §3.2 的回退链给 `i18n_list` 选当前语言文本。

`HostListCatalog` 负责生成列表：`rebuildI18nListLocked()` 遍历
`i18n_source_list`（解析每条 `texts`）→ 加 core 显示文案与 `@meta` →
`installGeneratedList("i18n_list", …)`；内容真的变了才排入 `lists.changed`。

## 7. 已知限制（本期刻意不做）

| 限制 | 说明 |
| --- | --- |
| RTL（阿拉伯语/希伯来语） | **不支持**：ImGui/Win32 混排的 RTL 布局没有验证过，本期不做镜像布局 |
| 日/韩/阿拉伯字体 | 设置页当前加载 `msyh.ttc`（微软雅黑），中日英字形可用；韩文/阿拉伯文需要字形回退（fallback font），现在会显示方块 |
| 首批译文只有 zh-CN + en-US | 注册表已注册 27 个可选标签（Latin/Cyrillic/Greek/日文字母族），但只有中英有译文：选其它语种时界面文案按回退链落 en-US，zh-TW 落 zh 族（简体）。补译文 = 宿主文案表加 `{tag,text}` + 各插件语言表加一张 JSON |
| 日期/数字格式 | 不做本地化：保存文件名的时间戳等仍是程序拼的固定格式 |
| `auto` 的平台覆盖 | 只有 Windows 做系统语言探测；其它平台固定 `en-US` |
| 新插件 + 老宿主 | 老宿主不生成 `i18n_list`：新插件的 label 会显示成 key 原文（老插件显示字面量不受影响） |
| 插件显示名/描述 | metadata 的 name/description 不本地化（P3 可选，用 `plugin.name` key 的方案） |
| 外部翻译覆盖 | 不支持用户自带翻译文件覆盖内置文本 |
| 离线 SDK 的 nlohmann-json | 汇总头 `shot_plugin_helpers.h` 现在会带进 `<nlohmann/json.hpp>`（i18n 语言表解析）；用离线 SDK 的插件工程需要自行提供 nlohmann-json（`vcpkg install nlohmann-json` 或头文件），见 `document/README_SDK.md` |

## 8. 检查清单

- [ ] 新增/修改用户可见文案时，同步更新 zh-CN 与 en-US 两张语言表，key 集一致？
- [ ] 配置项 `label`/`tooltip` 写的是 key（而不是中文），key 与语言表 `id` 一致？
- [ ] 托盘命令 `label` 用的是命令 id 作为 key？
- [ ] 自己的 UI 文案用 `tr(key, 原中文)` 兜底，没有把中文硬编码在渲染处？
- [ ] 日志、事件主题、配置 key、ENUM 存储值没有被翻译？
- [ ] 消费方新增显示字段时用了 `display(owner, value) ?? value` 规则？
- [ ] `lists.add` 的 owner 是当前插件 id、负载远小于 64 KiB？
- [ ] 宿主生成的列表（`i18n_list`）没有插件写入口？
- [ ] 改了解析规则/回退链？→ 同步本文件与 `LISTS.md`、`SETTINGS.md`。
