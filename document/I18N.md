# 多语言（i18n）协议

这份文档定义"界面文案怎么跨语言、跨插件共享"：语言偏好、两个 i18n 列表的 schema、
文本 key 的书写与回退链、插件侧 helper 与宿主侧 `Host::I18n` 的分工，以及本期的
明确限制。**新增用户可见文案、给配置项改 label、或者给插件加语言表之前先读这里**；
通用列表协议本身见 [`LISTS.md`](LISTS.md)，配置/设置页链路见 [`SETTINGS.md`](SETTINGS.md)。

**零 ABI 改动**是硬约束：i18n 只用 `shot.host.plugin_lists` + `lists.*` 事件，
不改 `include/plugin_api.h`、不新增 interface id / 宿主服务 / 插件能力，
`SHOT_ABI_MINOR` 不动，插件 metadata 也不用加字段。

## 1. 设计：数据形状不进 ABI

i18n 没有引入任何新 ABI，而是复用"数据列表 = list id + JSON schema"的通用容器：

```text
插件 create()
  └─ shot::I18n::loadTables(kLangTables) ── lists.add ──▶ i18n_source_list
                                                           （贡献 {id, texts:{tag:text}, target?, priority?}）
宿主 main 线程 tick
  └─ HostListCatalog::rebuildI18nListIfDirty() / rebuildI18nList()
        i18n_source_list + core 文案 + 语言目录 ──▶ 生成只读 i18n_list
        └─ lists.changed({"list":"i18n_list"}) ──▶ 设置页/托盘/其它插件刷新

消费方（设置页 / 托盘 / 插件）
  display(owner, textOrKey) = i18n_list[(owner, textOrKey)] ?? textOrKey
```

三条长期约定：

1. **数据列表里直接放 key**：`config_list` 的 `label`/`tooltip`、`tray_command_list`
   的 `label` 都允许是"字面量或文本 key"。所有显示方统一用上面的 `display` 规则；
   老插件把中文直接写在 label 里 → 查不到 → 原样显示（**零破坏、不用重编**）。
2. **谁渲染谁解析**：设置页解析配置项的 label/tooltip/ENUM 选项；托盘解析菜单
   label；插件自己的气泡/覆盖层用 `shot::I18n::tr()` 本地解析。
3. **宿主自己产生、被原样展示的文本由宿主本地化**，不走 key：插件注册表 `reason`、
   `capture.failed.reason`、`lists.updated.reason` 等。参数只有宿主知道，消费方只
   负责显示。

## 2. 两个列表

### 2.1 `i18n_source_list`（插件 / 语言包贡献）

插件在 `create()`/`init()` 里通过 helper 把自己语言表归一成条目后 `lists.add`；
外部语言包由翻译插件按同一 schema 贡献（见 §3.3）：

```json
{"list":"i18n_source_list","owner":"hotkey.main","items":[
  {"id":"config.capture_hotkey.label","texts":{"zh-CN":"截屏热键","en-US":"Capture hotkey"}},
  {"id":"config.capture_hotkey.tooltip","texts":{"zh-CN":"按一次组合键…","en-US":"Press a combo…"}}
]}
```

| 字段 | 类型 | 必填 | 含义 |
| --- | --- | --- | --- |
| `id` | string | ✅ | 文案 key，在合并后的 `(target, id)` 内唯一（通常等于消费方要解析的字段值）。`@meta` 是保留 id，宿主直接丢弃；以 `@language/` 开头的 id 是语言声明，不作文本条目（见下） |
| `texts` | object / string | 文本条目 ✅；语言声明可省 | `语言标签 -> 文本`；标签按 BCP-47（大小写不敏感、`_` 视同 `-`，宿主归一）；**空串视为缺失**，不入表。语言声明里也可以直接写字符串（只给显示名） |
| `target` | string | 可选 | 这条文本给哪个 owner 用：`"core"` 或当前已加载的插件 id；缺省 = 贡献者自己。非字符串、或不是 `core`/已加载插件 → 宿主丢弃该条并 WARN |
| `priority` | integer | 可选 | 同 `(target, id, 语言)` 多来源竞争时的权重，缺省 `100`。数值越大越优先；同 priority **后到者胜**。内置 core 文案 = 100、官方语言包 = 200、用户语言包 = 300 |

- 合并键是 **`(target, id, language)`**，不是 `(owner, id)` 整体：不同语言可以来自不同来源/优先级，胜出文本按语言各算各的。
- 内置 core 文案先以 priority=100 合并，随后才合并 source 条目；所以同 priority 的 `target=core` 条目也会覆盖内置文本（旧插件默认 priority=100 的行为保持不变）。
- **保留 id 与语言声明**：
  - `id == "@meta"` 被宿主拒绝（`i18n_list` 的首条固定是 `@meta`）。
  - `id == "@language/<tag>"` 是**语言声明**，只扩展语言目录，不产生文本条目；`<tag>` 归一化后为空则丢弃：
    ```json
    {"id":"@language/ja-JP","texts":{"ja-JP":"日本語"},"fallback":"en-US"}
    ```
    `texts` 可以是 `{tag: 显示名}` 对象，也可以直接是字符串（只给显示名）；显示名取 `texts[tag]` > 条目 `@meta`（字符串或对象 `name`）> `<tag>`；`fallback` 取条目 `fallback` > `@meta.fallback` > 默认 `en-US`。
- 写：插件 `lists.add` / `lists.remove`；owner 必须是当前已加载插件 id；宿主按
  `(list, owner, id)` upsert；插件卸载时宿主自动 `removeOwner` 清掉它的全部贡献。
- 读：宿主只读；**插件不能直接读 `i18n_source_list` 做解析**——解析一律走
  `i18n_list`，这样消费方只需理解一份数据。
- 单条事件负载上限 **64 KiB**（`document/EVENT_BUS.md` §5）：helper 按 **56 KiB** 预算分块
  （留 8 KiB 给 list/owner/items 外壳与 JSON 转义），单条 item 自身超限时跳过并 WARN；
  `lists.remove` 的 `ids` 数组也按同一预算分块。手写 `lists.add` 时同样要分块。
- 坏条目只跳过（WARN），不影响同批其它条目；宿主不会因为 i18n 数据让任何插件失败。

### 2.2 `i18n_list`（宿主生成、只读、当前语言快照）

宿主按当前语言把 core 文案 + 所有 `i18n_source_list` 条目投影成一份快照：

```json
[
  {"id":"@meta","language":"en-US","fallback":"en-US"},
  {"owner":"core","id":"settings.open","text":"Open settings"},
  {"owner":"core","id":"auto","text":"Follow system"},
  {"owner":"core","id":"en-US","text":"English"},
  {"owner":"core","id":"fr-FR","text":"Français (untranslated)"},
  {"owner":"core","id":"ja-JP","text":"日本語"},
  {"owner":"hotkey.main","id":"config.capture_hotkey.label","text":"Capture hotkey"}
]
```

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `id` | string | 条目 id；首条固定是 `@meta` |
| `owner` | string | 贡献方：`"core"` 或插件 id（`@meta` 没有 owner） |
| `text` | string | 该 key 在当前语言下的文本 |
| `language` | string | 仅 `@meta`：当前生效语言（BCP-47） |
| `fallback` | string | 仅 `@meta`：当前语言回退链的下一站（语言声明/注册表给出，缺省 `en-US`；zh 系为 `zh`） |

- **插件不能 add/remove `i18n_list`**：它是宿主生成的 `generated` 列表，写入口
  直接拒绝并 WARN（防手滑；`config_list` 同样处理）。
- 语言下拉的显示名也在这里：`owner="core"`、`id=<tag>` 的条目是语言目录里每个 tag
  的显示文本；`auto` 也是 core 条目。没有精确匹配译文的 tag 会带「（未翻译）」后缀
  （见 §3.1）。消费方仍按 `display("core", tag)` 解析。
- 生成时机：`HostRuntime::init` 里 **`loadPlugins` 之前**先用内置 core 文案重建一次
  （保证首个 tick 前设置页/托盘能读到文案）；插件加载完成后再重建一次；之后
  `core/language` 变化、`i18n_source_list` 贡献变化、`@language/` 目录变化、插件启停/
  卸载清理都会置脏。全部在 `HostRuntime::tick` 里重建完再统一 `flushChanged`，
  每轮每个 list 只发一条 `lists.changed`。
- 变化通知**只复用 `lists.changed`**（负载 `{"list":"i18n_list"}`），不新增事件主题。

### 2.3 解析规则（所有消费方必须一致）

```text
display(owner, textOrKey) = i18n_list[(owner, textOrKey)] 存在 ? text : textOrKey
```

- ENUM 选项也走同一规则：`display = resolve(owner, optionValue) ?? optionValue`。
  core 语言下拉因此能显示「跟随系统 / 简体中文 / 繁體中文 / English」，日志级别
  能显示「调试 / 信息 / 警告 / 错误」，而配置里存的仍是技术值（`auto` / `debug`）。
- 查不到时**原样返回 key/字面量**：这是老插件与新宿主、新插件与老宿主之间的
  兼容兜底，不是错误。

## 3. 语言偏好与语言目录

### 3.1 `core/language` 配置项

- 宿主设置里的 `core/language`（ENUM，默认 `auto`）：`auto` 或**语言目录里的 tag**。
  候选不是硬编码：`auto` 之后按目录顺序追加，目录 = 内置注册表 ∪ 外部语言包声明
  （见 §3.3）；当前内置 27 个标签，外部包可继续扩展。ENUM 的**存储值**始终是技术 tag。
- `set_config` 立即切换当前语言（与其它配置一致，落盘由 `lists.commit` 负责）；
  `HostRuntime::tick` 每轮对比当前语言，发现变化就强制重建 `i18n_list` 并刷新
  注册表快照——所以走 `applyStored` 回灌、`host.config` 写入这类非 `lists.update`
  路径切语言也不会漏重建。
- 语言目录在 `src/hostI18n.cpp`：内置注册表是 `tag + 原生显示名 + fallback` 的表驱动
  数据；语言包用 `@language/<tag>` 声明运行期追加。`HostListCatalog::rebuildI18nList()`
  每次重建都把声明通过 `setExternalLanguages()` 换入（内容不变不翻版本号）。
- **显示名**：设置页语言下拉的每一项按 `display("core", tag)` 从 `i18n_list` 取文本，
  优先级 = 语言包为 `<tag>` 提供的 core 文本 > 声明里的显示名（`texts[tag]` /
  `@meta.name`）> 注册表原生名 > 标签本身。原生名不随界面语言变化。
- **未翻译后缀**：某个 tag 在合并表里**没有任何一条精确匹配该 tag 的非空文本**时，
  显示名后追加当前语言的 `language.untranslated` 文案（中文「（未翻译）」、英文
  ` (untranslated)`）；不隐藏候选，只提示"选了会看到回退语言"。zh-TW 虽然能回退到
  zh-CN 的简体，也仍然算未翻译。
- **目录变化**：`@language/` 声明增删会翻 `Host::I18n` 的目录版本号。设置页的 ENUM
  候选由 `languageOptions()` 按目录版本号重算；`HostListCatalog` 同时标脏
  `config_list`，由 `HostRuntime::tick` 在持生命周期锁时重建——所以语言包加载/卸载后
  下拉候选与 `i18n_list` 会一起更新，不需要重启。
- 加内置语种 = 注册表加一行 + 宿主文案表每条加一项 `{tag, text}` + 各插件语言表加一张
  JSON——**不改宿主代码、不改列表协议**；只加语言包（不改代码）走 §3.3。
- 当前内置注册表包含 27 个标签：zh-CN / zh-TW / en-US，以及 fr-FR / de-DE / es-ES /
  pt-BR / it-IT / nl-NL / sv-SE / da-DK / nb-NO / fi-FI / pl-PL / cs-CZ / sk-SK /
  hu-HU / hr-HR / tr-TR / ru-RU / uk-UA / bg-BG / el-GR / ja-JP / ro-RO / id-ID /
  ms-MY。
  **仓库内置的首批译文只有 zh-CN 与 en-US**；其余标签可以选择，未翻译文案按回退链落
  `en-US`（zh-TW 落 zh 族简体），也可以由外部语言包补译文（§3.3）。
- `auto` 的解析：Windows 用 `GetUserDefaultLocaleName`；其它平台回退 `en-US`；
  系统标签不在目录里时先按主语言族匹配已注册语言（如系统报 `zh-HK` 落到
  `zh-CN`），仍没有才回退 `en-US`。
- 已保存的偏好如果是语言包 tag（例如 `ja-JP`），启动时它还没出现在目录里：先按 `auto`
  起步并记住这个值，等 `@language/` 声明到达后自动切回去，用户不需要每次重选。

#### 字体与字形覆盖

- 设置页是 **ImGui 1.92 + OpenGL3**；后端实现 `ImGuiBackendFlags_RendererHasTextures`，
  字体图集**按需烘焙**（用到哪个字形才光栅化），`ImFontConfig::GlyphRanges` 不参与。
  `GlyphRanges` 只在"后端不支持动态图集、退回 legacy 预烘焙路径"时生效——旧文档
  "中文字体区间不含 Cyrillic/Greek 就会显示 ?"只对 legacy 路径成立，不是现在的表现。
- 代码仍然显式补齐 **3929 个码位**的区间：中文常用字 + Latin-1 / Latin Extended-A /
  Latin Extended-B 的 `ȘșȚț` / Greek / Cyrillic + Supplement / 常用标点 / CJK 标点与
  假名 / 全角，让 legacy 后端也有完整字形。
- 主字体候选：Windows 依次 `msyh.ttc` / `msyhbd.ttc` / `simhei.ttf` / `simsun.ttc`，
  macOS / Linux 各有候选。`simhei` / `simsun` **实测缺 Latin Extended-A、Greek、
  Cyrillic**；`msyh` 也缺少量扩展字形（如 U+021B）。
- 所以主字体缺字形时，设置页用 `ImFontConfig::MergeMode` 把 `segoeui.ttf`（缺省再试
  `arial.ttf`）合进同一字体，只补主字体没有的字形；启动日志打印
  `中文字体 <path> + 补字字体 <path>` 和
  `字形覆盖：区间 3929 个码位，主字体缺 N 个字形，合并后…`。
- 仍然的限制：注册表不含韩/泰/阿拉伯/希伯来/越南等（字体无字形或需要 RTL 布局）；
  非 Windows 的字体候选路径未真机验证，全部找不到时退回 ImGui 内置字体
  （中文与扩展字母会显示成方块/问号）。

### 3.2 回退链（选文本，不是选语言）

```text
1 归一化 tag 完全匹配（大小写不敏感，_ 视同 -）
2 该语言的 fallback（@meta.fallback / 注册表 fallback；空串跳过）
3 该语言的主语言族（zh-TW 没有文本时命中 zh-CN）
4 fallback 的主语言族
5 默认语言 en-US
6 en 语言族（en-GB / en 表也能兜住）
7 第一条非空文本
8 都没有 → 消费方显示 key 原文
```

- **空串视为缺失**：不参与匹配，也不占"第一条非空"。
- `@meta.fallback` 是**当前语言的下一站**，由 `Host::I18n::fallbackTag()` 计算：
  语言声明的 `fallback`（`@language/<tag>` 的 `fallback` / `@meta.fallback`）> 内置
  注册表的 fallback > 默认 `en-US`。它不是"某条文本自己的回退字段"；它只影响回退链
  第 2 步，不改变语言目录或 ENUM。
- 宿主与插件 helper 的候选集合一致，实现分别在 `Host::I18n::selectText`（以及静态表的
  `pickFromTexts`）与 `shot::I18n::pickTagged`；族匹配阶段两边都试语言族与 fallback 族，
  相邻顺序略有差异（helper 先试 fallback 族），只在 fallback 与当前语言不同族时才有
  边角差别。改一处必须同步另一处。
- 首批内置译文只有 zh-CN + en-US：选择 `zh-TW` 时 zh 族没有专门文本，会落到
  `zh-CN` 的简体文本（**不是**繁体），这是本期的已知限制，见 §7。

### 3.3 外部语言包（`files/lang/` 与用户目录）

外部语言包 = **不改宿主编译、不改插件代码**，把译文以 JSON 文件放进约定目录，由翻译插件
（`plugins/translator`，插件 id `translator.main`，默认关闭，见本节末尾）扫描、校验后按
`i18n_source_list` 协议贡献给宿主。宿主本身**不读文件**，只认列表协议——没有翻译插件
（或它没启用）时，外部目录里的文件不生效。

#### 3.3.1 目录与优先级

| 来源 | 路径 | priority |
| --- | --- | --- |
| 官方语言包（随安装包） | `<exe 目录>/files/lang/<tag>.json`（构建时 `files/` 同步到 `bin/files/`） | `200` |
| 用户语言包（升级不覆盖） | `%LOCALAPPDATA%\plugin-shot\langs\<tag>.json` | `300` |
| `pack_dirs` 指定目录（配置项） | 非空时**只用它**（分号分隔多个目录，按书写顺序扫描），不再读上面两个默认目录 | `300` |
| 内置表（编译进宿主/插件） | 宿主 `kDisplayTexts` / 插件 `kLangTables[]` | `100` |

- 用户包 > 官方包 > 内置表；用户包可以覆盖内置的 `zh-CN` / `en-US` 文本。
- 优先级作用在合并键 `(target, id, language)` 上；同 priority **后到者胜**（不区分来源）。
- 只扫描目录**顶层**的 `*.json`（扩展名大小写不敏感，不递归；`README.md` 等其它文件
  忽略）；一个语言一个文件，文件名即 BCP-47 标签。`@meta.tag` 与文件名不一致时 WARN，
  以 `@meta.tag` 为准。
- 语言包目录不存在、没有 `*.json` 或某个包读不了：安静跳过/只 WARN，不影响宿主与其它包。
- 用户目录的 Windows 路径是 `%LOCALAPPDATA%\plugin-shot\langs\`；其它平台用
  `$HOME/.plugin-shot/langs`（翻译插件负责解析）。

#### 3.3.2 文件格式

```json
{
  "@meta": { "tag": "ja-JP", "name": "日本語", "fallback": "en-US" },
  "texts": {
    "core":        { "settings.open": "設定", "capture.request": "撮影" },
    "hotkey.main": { "config.capture_hotkey.label": "撮影ホットキー" }
  }
}
```

- UTF-8；文件开头允许 UTF-8 BOM（读取方剥掉，不能把 BOM 带进 tag/key）。
- `@meta` 有两种写法：字符串 `"ja-JP"`（只给 tag），或对象
  `{"tag","name","fallback"}`（`tag` 必填，`name` / `fallback` 可省）。两种写法都会
  让翻译插件额外贡献一条 `@language/<tag>` 语言声明（见 §3.3.3）。
- `@meta.name` 省略时翻译插件把 **tag 本身**当显示名；对内置标签这会覆盖注册表原生名，
  想保留原生名就显式写 `@meta.name`。`@meta.fallback` 省略时用注册表 fallback /
  `en-US`。
- `texts`：`owner`（`core` 或插件 id）→ `key` → 文本。文本空串 = **缺失**，按回退链
  处理，不要用空串表示"故意显示空白"。
- 文件里不写 `target` / `priority`：翻译插件按 `texts` 的 owner 生成 `target`，按目录
  来源生成 `priority`（官方 200 / 用户包与 `pack_dirs` 300）。

#### 3.3.3 翻译插件贡献给宿主的列表条目

翻译插件对每个**语言（tag）**发一条 `@language/<tag>` 声明（同 tag 的多个包先合并
显示名与 fallback），再把每条文本转成 `i18n_source_list` 条目：

```json
[
  {"id":"@language/ja-JP","texts":{"ja-JP":"日本語"},"fallback":"en-US"},
  {"id":"settings.open","texts":{"ja-JP":"設定"},"target":"core","priority":200},
  {"id":"config.capture_hotkey.label","texts":{"ja-JP":"撮影ホットキー"},"target":"hotkey.main","priority":200}
]
```

- `@language/<tag>` 只扩展语言目录，不作文本条目；`texts[tag]`（或 `@meta.name`）是下拉
  显示名，`fallback` 是该语言的下一站（缺省用注册表 / `en-US`）。
- 文本条目的 `target` 必须是 `core` 或**当前已加载**的插件 id；否则宿主丢弃并 WARN。
  所以给未安装插件准备的条目不会进 `i18n_list`，装上插件后需要翻译插件重新贡献。
- 用户包同样写法，只是 `priority` 是 300；官方包与用户包同 tag、同 key 时用户包覆盖
  官方包。**同 priority 后到者胜**，翻译插件应保证先贡献官方包、再贡献用户包。

#### 3.3.4 语言目录与语言下拉

- 语言目录 = 内置注册表 ∪ `@language/` 声明（内置在前，外部按 tag 排序）。
- 显示名优先级：语言包为 `<tag>` 提供的 core 文本（`target=core, id=<tag>`）> 声明的
  `texts[tag]` / `@meta.name` > 注册表原生名 > tag 本身。
- 目录里**没有任何精确匹配译文**的语言，显示名追加「（未翻译）」（英文
  ` (untranslated)`），不隐藏；见 §3.1。
- `core/language` 的 ENUM 候选 = `auto` + 目录顺序（当前 27 个内置 + 外部声明）；
  候选值仍是技术 tag。目录变化时 `languageOptions()` 重算，`HostListCatalog` 标脏
  `config_list`，下一轮 tick 重建——语言下拉与 `i18n_list` 一起更新，不重启。
- 已保存的 `core/language` 如果是语言包 tag（例如 `ja-JP`），启动时先按 `auto` 起步，
  等语言包声明到达后再自动切回去（`Host::I18n` 的 unresolved preference）。

#### 3.3.5 校验与错误处理

| 情况 | 行为 |
| --- | --- |
| 文件不是合法 JSON / 缺 `@meta` / 缺 `texts` / tag 无效或为空 / 没有一条可用文本 | 跳过该文件，WARN；翻译插件继续加载其它包，不失败 |
| 单个文件超过 4 MiB | 按坏包跳过，WARN（语言包通常只有几 KB，多半是放错文件） |
| `@meta.tag` 与文件名不一致 | WARN，以 `@meta.tag` 为准 |
| 文本值不是字符串 / 空串 | 跳过该条（空串按缺失处理） |
| 文本条目 `id == "@meta"` | 宿主拒绝（`i18n_source_list` 保留 id），WARN |
| `target` 不是字符串 / 不是 `core` 或已加载插件 | 丢弃该条，WARN |
| `priority` 不是整数 | WARN，按缺省 `100` 处理 |
| 单个条目估算后超过 56 KiB / 单条事件超过 64 KiB | 翻译插件应分块；单条自身超限时跳过并 WARN（发出去也会被宿主整条丢弃） |
| 语言包目录不存在 / 没有 `*.json` | 安静跳过（翻译插件仍正常加载） |

- **坏包只 WARN，翻译插件不失败**：解析失败只能影响该包，不能把翻译插件或宿主带崩；
  其它包与内置文案照常工作。
- 语言包文件内容不参与日志正文翻译；错误日志保持中文（日志不翻译，§4）。

#### 3.3.6 翻译插件（`translator.main`）

- 扫描目录、解析/校验、按目录来源设 priority、贡献 `@language/` 与 `target` 条目都由
  `plugins/translator`（插件 id `translator.main`，`shot.configurable`）承担；宿主侧协议
  已实现（`i18n_source_list` 的 `target` / `priority` / `@language/` 与合并层）。
- 配置项（存盘键 `translator.main/<key>`）：
  - `enabled`（BOOL，默认 `"0"`）：是否加载外部语言包。**默认关**——一开就会改写 core
    文案，现有 e2e 断言按内置中英文写。
  - `pack_dirs`（PATH，`options="directory"`，默认空）：空 = 官方 + 用户两个默认目录；
    非空 = 只用它，多个目录用分号分隔（priority 300）。
- 关闭 / 删包 / 换目录时翻译插件先 `lists.remove` 再重新发布，关闭效果等于"从没加载
  过"。它**不监听文件系统**：只改包文件不会自己生效，改 `enabled` / `pack_dirs`
  或下一次重扫才会重新读取（配置变化走 `lists.changed` 回调）。
- 扫描到坏包只 WARN；包文本能否覆盖某条文案，取决于该文案是否走 `i18n_list` 解析
  （插件自己 `tr()` 的本地表不受语言包影响），见 §4。
- 验证脚本 `tools/verify/smoke_i18n_translator.ps1` 已登记（见
  [`tools/verify/README.md`](../tools/verify/README.md)）。

## 4. 文案归属与不翻译的东西

| 谁产生 | 怎么本地化 | 例子 |
| --- | --- | --- |
| 插件贡献的数据字段（`label`/`tooltip`/ENUM 选项） | 值写成 key，消费方 `display()` 解析 | `config.capture_hotkey.label` |
| 插件自己绘制的 UI（气泡、覆盖层、提示） | `shot::I18n::tr(key, 中文兜底)` 本地解析 | `ui.save_failed` |
| 宿主预置数据（托盘命令、core 配置项） | 宿主把 label 写成 key，宿主文案表按语言生成 `i18n_list` 条目 | `capture.request` |
| 宿主生成、被原样展示的文本 | 宿主 `Host::I18n::Message` 按当前语言生成 | 注册表 `reason`、`capture.failed.reason` |

**一律不翻译**（写死为中文/技术值，翻译会破坏协议或验证体系）：

- 日志（`shot::Logger` / `spdlog`）：e2e 按中文日志断言，日志正文保持中文；
- 事件主题（`capture.request`、`lists.changed`…）、配置 key（`logging.level`）、
  列表 id；
- ENUM 的**存储值**（`auto` / `debug` / `png`）：只有显示名本地化；
- 插件 metadata 的 id/版本、窗口类名、DLL 名。

## 5. 插件侧用法（`shot::I18n`，header-only）

```cpp
#include "shot_plugin_helpers.h"   // 也可以只包含 shot_plugin_helpers/shot_i18n.h

// 一个 DLL 一个插件 / 一个 DLL 多个插件都行：owner 必须是被解析条目的 owner。
const char* const kLangTables[] = {
    R"json({"@meta":"zh-CN","config.strength.label":"强度"})json",
    R"json({"@meta":"en-US","config.strength.label":"Strength"})json",
};

// 在能拿到 ShotHostServices* 的生命周期回调里（create/init/start）：
m_i18n = std::make_unique<shot::I18n>(host, "example.invert");
m_i18n->loadTables(kLangTables, std::size(kLangTables));

// 自己的文案（本地表 O(1)，查不到返回中文兜底）：
label = m_i18n->tr("config.strength.label", "强度");

// 数据列表里的 key/字面量（查 i18n_list 缓存；老宿主原样返回）：
name = m_i18n->resolve(owner, item.label);
```

- 语言表：**每语言一张 JSON 对象**，`@meta` 必填，支持字符串
  `"@meta":"zh-CN"` 与对象 `{"tag":"zh-CN","name":"简体中文","fallback":"en-US"}`
  两种写法（对象里的 name/fallback 是给宿主语言目录的元数据，helper 只取 tag）。
  表文本允许 UTF-8 BOM；值空串按缺失，不写进表。
- 非法 JSON / 缺 `@meta` / 单张表没有可用文案 → 只 WARN 并跳过该表；各语言 key 集
  不一致只 WARN（缺的 key 走回退链）。`loadTables` 一张表都没解析成功时**保留旧表**
  （失败不半更新），插件不失败。
- 发布的是各语言 key 的并集，按 64 KiB 事件上限分块（helper 预算 56 KiB）；单条 item
  自身超限则跳过并 WARN。重复 `loadTables` 会先按同一预算分块撤回旧 key。
- helper 内部订阅 `lists.changed`，`i18n_list` 变化后下一次查询重读快照；
  渲染帧里只有 map 查找，不会每帧查宿主。
- 降级：老宿主没有列表服务 → `available()==false`，`tr()` 用第一张表、
  `resolve()` 原样返回；返回的 `const char*` 在 `i18n_list` 变化/对象销毁后失效，
  要长期持有请拷成 `std::string`。
- 对象不可拷贝/移动，状态里用 `std::unique_ptr` / `std::optional` 持有；
  销毁时自动退订。

## 6. 宿主侧（`Host::I18n`）

`include/hostI18n.h` + `src/hostI18n.cpp`，一个进程一个单例：

- `languages()` / `findLanguage()` / `normalizeTag()` / `detectSystemLanguage()`：
  语言注册表与 auto 解析；
- `loadPreference()` / `setPreference()` / `preference()` / `language()` /
  `fallbackLanguage()`：语言偏好与当前语言（启动时 `HostRuntime::init` 读配置，
  运行期由 `HostConfigurable` 的 `set_config` 写入）；
- `text()` / `textIn()` / `format()` / `formatIn()`：宿主文案表（显示文案 + 动态
  消息）；每条文案的 `texts` 是任意语言的 `{tag, text}` 列表，选文本按 §3.2 的
  回退链；`Message` 类把"消息 id + 参数"延迟到渲染时按语言生成；
- `selectText()`：给 `语言 -> 文本` 映射选文本的统一实现；`pickText()` /
  `pickTextIn()` 是它在当前语言/指定语言上的薄封装；`pickFromTexts()` 走同一组候选
  步骤，给 `text()` / `textIn()` 的静态表用；
- `catalog()` / `setExternalLanguages()` / `catalogVersion()`：语言目录与版本号；
  宿主不读语言包文件，目录里的外部语言完全由 `@language/` 声明驱动；
- `fallbackTag()` / `resolveLanguage()`：当前语言的回退下一站与偏好解析。

`HostListCatalog` 负责生成列表：`rebuildI18nListIfDirty()` 在启动/tick 检查脏标记，
`rebuildI18nList()` 解析 `i18n_source_list`（`texts` / `target` / `priority` /
`@language/`，剥 BOM、空串视为缺失）→ 合并内置 core 文案（priority=100）→ 一次取定
当前语言与 fallback → 用统一回退链投影 core 文案、语言下拉显示名（含未翻译后缀）与
其余 `(target,id)` 文本 → `installGeneratedList("i18n_list", …)`。目录变化时另标脏
`config_list`；内容真的变了才排入 `lists.changed`。启动时在 `loadPlugins` **之前**
先重建一次，保证首个 tick 前设置页/托盘就能读到 core 文案。

## 7. 已知限制（本期刻意不做）

| 限制 | 说明 |
| --- | --- |
| RTL（阿拉伯语/希伯来语） | **不支持**：ImGui/Win32 混排的 RTL 布局没有验证过，本期不做镜像布局 |
| 韩/泰/阿拉伯/希伯来字体 | 设置页按平台候选加载中文字体（日文字形可用），主字体缺字形时用 `MergeMode` 合并 Segoe UI / Arial 补 Latin Extended / Greek / Cyrillic；ImGui 1.92 动态图集按需烘焙（`GlyphRanges` 只影响 legacy 路径）。韩/泰/阿拉伯/希伯来/越南等没有注册，RTL 布局不支持；非 Windows 的字体路径未真机验证 |
| 首批内置译文只有 zh-CN + en-US | 注册表已注册 27 个可选标签（Latin/Cyrillic/Greek/日文字母族），但仓库内置译文只有中英：选其它语种时界面文案按回退链落 en-US，zh-TW 落 zh 族（简体）。补内置译文 = 宿主文案表加 `{tag,text}` + 各插件语言表加一张 JSON；不改代码补译文走外部语言包（§3.3） |
| 日期/数字格式 | 不做本地化：保存文件名的时间戳等仍是程序拼的固定格式 |
| `auto` 的平台覆盖 | 只有 Windows 做系统语言探测；其它平台固定 `en-US` |
| 新插件 + 老宿主 | 老宿主不生成 `i18n_list`：新插件的 label 会显示成 key 原文（老插件显示字面量不受影响） |
| 插件显示名/描述 | 插件可在语言表里贡献 `target=自己, id=plugin.name`，设置页配置分区显示译名（`config_list.owner_name_key`）；插件管理表格仍显示注册表里的 metadata name，metadata 的 description 不本地化 |
| 外部语言包 | **已支持**（`files/lang/` 官方包 + `%LOCALAPPDATA%\plugin-shot\langs\` 用户包，用户包 priority=300 可覆盖内置），见 §3.3；扫描/校验由 `plugins/translator`（`translator.main`，默认关）负责，坏包只 WARN |
| 离线 SDK 的 nlohmann-json | 汇总头 `shot_plugin_helpers.h` 现在会带进 `<nlohmann/json.hpp>`（i18n 语言表解析）；用离线 SDK 的插件工程需要自行提供 nlohmann-json（`vcpkg install nlohmann-json` 或头文件），见 `document/README_SDK.md` |

## 8. 检查清单

- [ ] 新增/修改用户可见文案时，同步更新 zh-CN 与 en-US 两张语言表，key 集一致？
- [ ] 配置项 `label`/`tooltip` 写的是 key（而不是中文），key 与语言表 `id` 一致？
- [ ] 托盘命令 `label` 用的是命令 id 作为 key？
- [ ] 自己的 UI 文案用 `tr(key, 原中文)` 兜底，没有把中文硬编码在渲染处？
- [ ] 日志、事件主题、配置 key、ENUM 存储值没有被翻译？
- [ ] 消费方新增显示字段时用了 `display(owner, value) ?? value` 规则？
- [ ] `lists.add` 的 owner 是当前插件 id、负载远小于 64 KiB？
- [ ] 外部语言包只放 `*.json`、tag 与文件名一致、空串当缺失、坏包只 WARN？
- [ ] 语言包条目的 `target` 只写 `core` 或已加载插件 id，priority 官方 200 / 用户 300？
- [ ] 宿主生成的列表（`i18n_list`）没有插件写入口？
- [ ] 改了解析规则/回退链？→ 同步本文件与 `LISTS.md`、`SETTINGS.md`。
